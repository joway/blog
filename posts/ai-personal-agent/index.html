聊天或许并不是个人 Agent 的正确打开方式

24 Sep 2026
@Joway

最近各家公司都发布了自己的 Personal Agent，这应该是我印象里，Agent 第一次以纯粹面向普通老百姓的 2C 形态落地。

从 openclaw 开始，我体验了各家个人 Agent 形态的产品，包括我自己为我自己写的，以及我自己为公司写的 Agent，我有一种感觉是，个人 Agent 其实是一个伪命题，或者说一个聊天形式的 Agent 并不是面向普罗大众的正确交互接口。下面是我认为的原因。

环保问题

乍一听这个理由，你可能会觉得特别离谱。作为一个中国人，其实我们从小是缺乏环保意识的。我也是成年后，看到了地球上出现的各种极端气候和污染问题，才开始认识到自己或多或少也应该出一份力。几年前开始，我每次去买早饭，即便塑料袋是免费提供的，在我空着手或背着书包的情况下，我都会要求店员不要给我提供塑料袋，每次这么做都会让我心理觉得罪恶感降低了一点点。

我在使用个人 Agent 的时候，当我看到这些 Agent 为了让我有那么几秒钟的惊喜收集了我这么多数据去进行了这么多运算，所产生的感受和我多用了一只塑料袋的感受是一样的。而 Coding Agent 不会给我产生这样的感受是因为我是用它来创造价值的而不是个人消遣。

成本问题

Coding Agent 的成本大部分时候由公司支付，最终由公司创造价值并让消费者间接承担这个成本。如果没有创造价值，那么公司就会亏损。所以这个故事在商业上是成立的。

个人 Agent 无论目前是否收费，最终的成本归根结底也还是得消费者自己支付，创造的价值一方面取决于产品提供了什么功能，另一方面也取决于消费者如何用。

那么目前这些产品都提供了哪些功能呢？预定餐厅，查询天气，个人待办事项提醒，个性化新闻流。我不认为用户会愿意为了这些琐事支付太多费用，特别是，这些琐事本就是人生的一部分。有可能是中国人和美国人生活都太忙，都太卷，我生活在新加坡，每天的最大烦恼就是今天要做什么，如果连生活的琐事都不需要做了，我不知道人还能做什么事情充实自己的生活。

此外，还有一个巨大的生活差异我觉得是被现在富裕的创业者遗忘的。我在欧洲和东南亚都生活过，我见到的大部分人每天的生活都是在研究如何省钱，而不是花钱，尤其是现在通货膨胀和生活费用高涨的年代。如果用 Agent 花 30s 查个天气就要一块钱，我绝对愿意浪费自己的时间花 60s 去 Google 查。坦率讲我真的也不是真的很在乎这一块钱，但是在这种高物价国家生活，省钱是一种高级的生活娱乐，这个真的只有在这种国家生活过且花的是自己而不是爸妈钱的人才能体会。我觉得现在的创业者是忘记了全世界普通老百姓的生存状态的，特别是中国人。

使用门槛

一个 2C 软件应该是面向普通老百姓设计的而非精英。如果你和很多人接触过你就会发现，大部分人是没有主动提出问题的能力的，即便要提出，也没有掌握正确的提问方式。我之前写了一篇文章探讨为什么同样是用同一个 Coding Agent，每个人的产出质量差异会如此之大，根因就在于人的提问能力有巨大差异，而现在的 AI Agent 强依赖人的聊天能力。你会聊天，你可以把 AI 用出花来，你不会聊天，AI 真的就只能帮你查个天气而已。

现在的 Agent 希望自己的能力是泛化的，所以一切功能都来自于用户的自然语言输入，而一个人的真实世界行为其实主动发起聊天是极少的场景，大部分我们的数字生活都是被动的。被动被推荐新闻短视频，被动刷 Ins 流，被动决定晚饭吃什么，正是这些被动才使得我们的生活变得轻松，主动的人生是值得追求的但是非常累。

我认为的个人 Agent 的形态

我认为 Agent 面向普通人的交互接口，不应该是聊天窗口。过去互联网已经创造了很多非常好用的交互接口，比如 TikTok 的视频流，比如小红书/Ins的图文流。而现在发生的事情无非是 AI 能力的提升，而不是出现了什么新的硬件，所以我不是很理解为什么做个人 Agent 一定要用聊天的交互方式。

举个例子，TikTok 完全可以搞一个 Tiktok Agent ，你虽然刷着短视频，但是后台会把你的定位，历史浏览记录发给云端 Agent ，如果马上要下雨了就推送你下雨提醒，如果你刷过一个餐厅打卡且你离他不远就推送你一个按钮一键预定。至于你实在是有一个疑问要打字问，你爱用哪家 AI 就用哪家 AI。

换句话说，Agent 应该是一种技术实现方法，而不是软件交互方式。

Agent 的技术原理其实很简单，就是「用户输入」-「模型推理」-「工具调用」-「模型推理」- … -「输出结果」。技术上并没有限定输入输出必须是以聊天的方式进行的。为什么现在大家都用聊天来承载着这个 Agent Loop 是因为这里的「用户输入」是一个不确定的输入。之前软件的所有输入都是确定性的，比如输入了密码，点击了登录按钮，批准了申请。而现在因为不确定，所以你只能让用户用文字描述自己的需求，就算现在这个 action 就是要点击登录按钮，你也得让用户输入文字 “登录” 才能进行下一步。

我认为的务实的交互方式是，利用现存软件已经积累的数据资产和 UI ，在背后让软件的实现方式变成 Agent 化。以前你淘宝搜一个「茶几」，是直接用推荐引擎算法排序返回结果，而未来，它可以是让后台 Agent 根据你的信息先给你生成几个风格选项，价格区间选择，甚至调用小红书实现的 Tool 接口获取你的浏览数据再给小红书一些提成，最后给你返回的是 Agent Loop 执行完毕后的结果。Agent 对用户的存在感应该是很低的。最关键的是，这些平台有动力支付成本让这个 Agent Loop 运行。普通用户是不愿意为了买个茶几额外支付推荐成本的，而平台本来就有销售成本预算。

如果你把这个 Agent 实现在这些已经存在的大公司软件生态之外，你一定会遇到的问题是，淘宝和小红书不希望你用 AI 来获取数据，因为这和他们的利益不符。这就是不是交互接口用户喜不喜欢的问题了，而是大平台不接受用户的交互入口居然是你的 Agent 而不是他们自己的平台，
